# 角色触摸动作配布编写指南

本文以正常版巧克力（`chocola`）为例，说明怎样把一条语音配成完整的“触摸 → 初始反应 → 说话中的变化 → 恢复”动作。示例使用项目已有的摸头、碰脸语音；适用于当前 `index.php`、`main.js` 和 `reaction-library.js`。

## 1. 先了解文件之间的关系

| 文件或目录 | 作用 |
| --- | --- |
| `config/chocola-config.js` | 巧克力每条语音的触发区域、表情、动作和时间安排。网页调用其中的 `getConfig()`。 |
| `config/reaction-library.js` | 把角色文件里的简写数组转换成播放器使用的完整对象，并添加默认恢复动作、无声闭眼反应。 |
| `main.js` | 负责区域判定、随机选择反应、播放语音、口型同步、执行中途变化和恢复动作。 |
| `index.php` | 决定某个模型使用哪份配置，并按顺序加载公共库和角色文件。 |
| `sounds/chocola/` | 巧克力的 WAV 语音文件。 |
| `model_conversion/chocola/` | 各模型的中间 JSON，可以查可用动作名、变量及其标注值。 |

页面先加载 `reaction-library.js`，再加载一个角色配置文件。不要同时加载几份角色配置，否则它们的 `getConfig()` 会互相覆盖。

`index.php` 中的模型映射例如：

```php
'chocola-maid' => [
    'use_config' => 'chocola-config.js',
    'psb_url' => './data/chocola-maid.pure.psb.zip'
],
```

同一个角色的不同服装可以复用一份配置，前提是其中所有动作和变量都被这些模型支持。幼年版本使用单独的 `ko*-config.js`，不能只换语音目录而照搬正常版的配布。

## 2. 从巧克力的三条语音开始

下面是**语法完整的教学示例，只包含三条语音**。实际的 `chocola-config.js` 包含更多条目；修改时应保留现有条目，不要用这个精简示例覆盖全部配布。

```js
function getConfig() {
    return NekoReactions.create(
        'chocola',
        '开朗率直，主动亲近；笑容和点头较明显。',
        [
            // 短语音：摸头或碰脸时，微笑并点头。
            ['h01', 'head face', 1070,
                '喜ぶ00', 'うんうん', '轻快回应摸头'],

            // 短促反应：碰脸时吃惊；没有中途变化。
            ['h04', 'face', 469,
                '驚き00', 'びっくり2', '短促叫声，碰脸时小小一惊'],

            // 长语音：先轻微抱怨，在 1554ms 时平复并露出疑问。
            ['h06', 'face', 2391,
                '困る00', 'いやいや', '拖长低鸣，轻轻抱怨碰脸',
                [1554, '平常', '疑問']]
        ]
    );
}
```

第一项 `'chocola'` 对应 `sounds/chocola/`，不是模型文件名。第二项是角色配布说明，保存在配置的 `description` 属性中，不会直接播放或改变动作。

第三项数组中的**每一行代表一个声音对应的一套反应**。

| 行内位置 | `h06` 示例 | 怎样填写 |
| --- | --- | --- |
| 1：声音名 | `'h06'` | 不带目录、不带 `.wav`。最终路径为 `./sounds/chocola/h06.wav`。 |
| 2：触发区域 | `'face'` | 一个区域名；多个区域用单个空格分开，例如 `'head face'`。不要写成 `'head,face'`。 |
| 3：保持时间 | `2391` | 毫秒，通常填写 WAV 的实测时长。它不是语音播放速度。 |
| 4：主时间轴 | `'困る00'` | 必须是该模型支持的主动作标签，日文拼写要完全一致。 |
| 5：叠加时间轴 | `'いやいや'` | 必须是 diff 动作标签；不用叠加动作时填写空字符串 `''`。 |
| 6：意图说明 | `'拖长低鸣…'` | 说明语气与演出意图，供配置维护使用，不参与动作控制。 |
| 7：中途变化 | `[1554, '平常', '疑問']` | 可省略。依次是变化时间、后续主时间轴、后续叠加时间轴。 |

`'head face'` 会让两个区域引用同一个反应对象，因此同一个声音在两个区域的表现保持一致。不要为同一条语音在不同区域另写互相矛盾的情绪。

公共库会额外添加一个无声眼部反应，ID 为 `chocola/blink`，所以教学示例返回的配置中还会有 `eye` 条目。

### `h06` 实际怎样播放

1. 点击命中脸部，播放器从 `face` 数组中等概率随机选出一条反应。`h06` 不保证每次都会被选中。
2. 如果选中 `h06`，立即设置 `困る00` 和 `いやいや`，并加载、播放 `h06.wav`。
3. 音频准备完成后开始安排中途变化；约在第 1554ms 换成 `平常` 和 `疑問`，语音继续播放。
4. 等配置保持时间、初始主时间轴和语音满足结束条件后，停止口型驱动，执行恢复动作。
5. 默认再等待 320ms 的恢复间隔，才允许触发下一次反应。

声音名只是文件编号，不能据此认定情绪。先听语气、停顿、笑声或叫声，再决定表情和动作。以上文字是当前配布的设计意图，不是经人工听审确认的逐字台词。

## 3. 触摸区域如何填写

`getConfig()` 最终返回以下五个区域数组：

| 配置键 | 当前命中方式 | 优先顺序 |
| --- | --- | --- |
| `bust` | 距模型对应 marker 小于 50 屏幕像素。 | 1 |
| `eye` | 距眼部 marker 小于 30 屏幕像素。 | 2 |
| `face` | 距头部中心下方 40px 的点小于 80 屏幕像素。 | 3 |
| `head` | 距头部中心小于 120 屏幕像素。 | 4 |
| `pant` | 距对应区域中心小于 180 屏幕像素。 | 5 |

这些区域是现有播放器的接口名称。圆形区域可能重叠，先命中的**有反应条目**的区域先播放；数组为空时会继续检查后面的区域。没有命中有配置的区域就不触发反应。

半径按屏幕像素计算，不会随模型缩放等比例改变，也不是精确的身体网格命中。因此，动作配置正确并不代表实际点击一定能命中对应区域，仍需按实际画面检查。

配置数组没有权重、固定播放顺序或独立冷却时间：每个条目被等概率抽取，播放及恢复间隔期间会阻止重复触发。普通 `duration` 和 `recoveryDuration` 字段不能用来设置“某条声音出现的概率”。

当前代码只识别以上五个键。若要新增耳朵、手臂等区域，需要在 `main.js` 增加命中判定及配置读取，并使用可靠的模型位置依据；只在配置里添加 `ear` 或 `arm` 不会自动生效。

## 4. 主动作与叠加动作怎样搭配

主时间轴负责主要表情或姿态，叠加时间轴负责点头、摇头、微笑等补充动作。选择时应让两者表达同一种情绪，避免一个表示拒绝、另一个持续兴奋地点头。

以下是巧克力模型中的常见标签，名称解释用于帮助查找，具体效果仍应看模型：

| 类型 | 标签举例 | 适用意图 |
| --- | --- | --- |
| 主时间轴 | `平常` | 回到常态。 |
| 主时间轴 | `喜ぶ00`、`喜ぶ01`、`喜ぶ02` | 不同的高兴表情或姿态。 |
| 主时间轴 | `楽しい00`、`楽しい01`、`楽しい02` | 不同的愉快表情或姿态。 |
| 主时间轴 | `驚き00`、`驚き01`、`驚き02` | 吃惊。 |
| 主时间轴 | `困る00`、`困る01`、`困る02` | 困惑、为难。 |
| 主时间轴 | `怒る00`、`怒る01`、`怒る02` | 生气或抗议。 |
| 叠加时间轴 | `うん`、`うんうん` | 点头。 |
| 叠加时间轴 | `疑問`、`戸惑い` | 疑问、犹豫。 |
| 叠加时间轴 | `いやいや`、`いやいや2` | 摇头。 |
| 叠加时间轴 | `にっこり`、`にっこり2`、`ごきげん` | 微笑或放松的表现。 |

`00`、`01`、`02` 不是统一的强度等级。不同角色或服装，同名动作也可能有不同姿势。

公共库默认生成六个槽：

```js
const slots = ['うんうん', '', '', '差分用_waiting_loop', '', ''];
```

数组第 1～6 项分别对应 `diffTimelineSlot1`～`diffTimelineSlot6`。第四槽保留待机动作，其余未使用槽明确清空。这样既不会残留上一条反应的叠加动作，也不会触发旧逻辑按区域额外随机添加第三槽动作。

一个 diff 时间轴可以控制多个变量。叠加越多不一定越自然；两个时间轴同时控制头部、眼睛或嘴形时，可能发生互相覆盖，应逐项试听。

## 5. 怎样查模型支持的动作和变量

以女仆巧克力为例，打开：

```text
model_conversion/chocola/chocola-maid/chocola-maid.json
```

重点看 `metadata` 中两个部分：

- `timelineControl`：每项的 `label` 是动作名；`diff: 0` 表示主时间轴，`diff: 1` 表示叠加时间轴。内部 `variableList` 展示时间轴控制哪些变量，能用来排查动作冲突。
- `variableList`：每项的 `label` 是变量名，`frameList` 中的 `frame` 和 `label` 表示数值与含义。同名变量可能出现多项，查范围时要合并查看。

例如巧克力的 `face_talk` 标注为 `0 = 閉じ`、`5 = 開き`；`face_eye_open` 的常规标注包括 `0 = 通常`、`10 = 閉じ`、`20 = 笑い`，另有特殊值。

也可以在模型加载完成后，在浏览器开发者工具控制台读取实际接口：

```js
const player = EmotePlayer.device.playerList[0];
console.log('主时间轴', player.mainTimelineLabels);
console.log('叠加时间轴', player.diffTimelineLabels);
console.log('变量及范围', player.variableList);
```

控制台读取本身不会修改模型。实际网页播放时，会过滤不存在的标签和变量；因此“没有报错”不等于“配置确实生效”。没有转换 JSON、或 JSON 与实际模型不一致时，应以运行时列表和视觉效果为准。

常见错误：

- `首横振り` 是巧克力的主时间轴，不能把它当 diff 标签放入叠加槽。
- 不要自行推导不存在的 `喜ぶ03`、`楽しい03`、`頬染め03`。
- 芙蕾兹的 diff 列表与其他角色有差异，不能照搬 `びっくり1`。
- 一个服装可用的动作，移植到同角色其他服装前也需要核对。

## 6. 需要更细的控制：编写完整对象

简写行只支持一项叠加动作和一次中途变化。需要多个变化点、自定义变量或独立恢复动作时，可以直接返回完整对象。这与播放器原来的对象结构相通；`beats`、`recoveryDuration` 则需要当前 `main.js` 支持。

下面仍以巧克力 `h06` 为例。**这是另一种教学写法，和第 2 节二选一，不要在同一个文件定义两次 `getConfig()`。** 示例只配置脸部一条语音及眼部闭眼，其他数组留空。

```js
function getConfig() {
    const idle = '差分用_waiting_loop';
    const slots = gesture => [gesture, '', '', idle, '', ''];

    const faceReaction = {
        id: 'chocola/h06',
        note: '先抱怨，再疑惑地平复',
        reaction: {
            mainTimelineLabel: '困る00',
            diffTimelineSlots: slots('いやいや'),
            audio: './sounds/chocola/h06.wav',
            variables: []
        },
        beats: [
            {
                at: 1554,
                mainTimelineLabel: '平常',
                diffTimelineSlots: slots('疑問'),
                variables: []
            }
        ],
        recovery: {
            mainTimelineLabel: '平常',
            diffTimelineSlots: slots(''),
            variables: [
                { name: 'face_talk', value: 0, duration: 120 },
                { name: 'move_LR', value: 0, duration: 240 },
                { name: 'move_UD', value: 0, duration: 240 },
                { name: 'body_slant', value: 0, duration: 240 }
            ]
        },
        duration: 2391,
        recoveryDuration: 320
    };

    const blink = {
        id: 'chocola/blink',
        note: '碰到眼睛：短暂闭眼',
        reaction: {
            // 停止当前主时间轴，避免它的眼睛参数覆盖手动闭眼。
            mainTimelineLabel: '',
            diffTimelineSlots: slots(''),
            variables: [
                { name: 'face_eye_open', value: 10, duration: 90 }
            ]
            // 无 audio，表示不播放语音。
        },
        recovery: {
            mainTimelineLabel: '平常',
            diffTimelineSlots: slots(''),
            variables: [
                { name: 'face_eye_open', value: 0, duration: 180 }
            ]
        },
        duration: 650,
        recoveryDuration: 220
    };

    return {
        bust: [],
        eye: [blink],
        face: [faceReaction],
        head: [],
        pant: []
    };
}
```

完整对象自身不依赖 `NekoReactions.create()`。`id` 是反应的维护标识，建议使用 `角色/声音名`，不同反应使用不同 ID，便于与语音分析记录对应；无声反应也可以有自己的 ID。多个区域需要同一套演出时，把同一个对象放进对应数组。

### 完整对象的字段

| 字段 | 含义 |
| --- | --- |
| `reaction` | 触摸时的初始动作配置。 |
| `reaction.audio` | 音频路径，相对于网页地址解析，不是相对于配置 JS 文件。当前站点使用 `./sounds/...`。 |
| `reaction.mainTimelineLabel` | 初始主时间轴。空字符串停止当前主时间轴。 |
| `reaction.diffTimelineSlots` | 六个叠加槽。数组不足六项时，后面的槽也会被清空。 |
| `reaction.variables` | 初始变量调整。无调整时用 `[]`。 |
| `beats` | 多个中途变化点；每项用 `at` 指定毫秒，再填写该阶段的完整动作配置。 |
| `recovery` | 结束后的动作配置；当前播放函数在清理阶段执行，包括音频加载失败的退出路径。 |
| `duration` | 从初始反应开始计算的最短保持时间。最终还会等待语音和初始主时间轴；最短 650ms。 |
| `recoveryDuration` | 恢复配置应用后等待多久再接受下一次触摸；不是所有变量的统一插值时长。省略时播放器用 180ms，公共库语音条目默认设置为 320ms。 |
| `id`、`note` | 配置标识与维护信息，不控制模型动作。 |

每个 `beat.at` 必须是有限数值，满足 `0 <= at < duration`；建议从小到大排列。不要在 `beat` 或 `recovery` 中放需要播放的声音，当前播放器只播放初始 `reaction.audio`。

`beats` 在初始音频准备完成后计时；静音或无音频时也可以执行。它不是“等上一项动作做完再执行下一项”的队列。每个变化点都应写明想保留的主时间轴与叠加槽：当前 `buildPlaybackConfig()` 会把缺省的主时间轴补成 `''`，不会自动继承前一阶段。

如果用 `diffTimelineSlot1`～`diffTimelineSlot6` 分别赋值，省略的槽通常保留原值；省略第三槽还可能触发播放器的区域补充动作逻辑。对新配布，明确填写 `diffTimelineSlots` 更容易控制最终效果。

## 7. 模型变量的填写方式

每个变量调整的格式如下，多个变量放进同一个 `variables` 数组：

```js
const variableAdjustment = {
    name: 'face_eye_open',
    value: 10,
    duration: 90,
    easing: 0
};
```

- `name`：当前模型支持的变量名。
- `value`：目标值，按模型 `frameList` 的标注含义选取。
- `duration`：从当前值过渡到目标值的毫秒数，**不是保持时间**。想保持闭眼 650ms，应使用反应外层的 `duration: 650`，并在 `recovery` 中重新睁眼。
- `easing`：传给驱动的插值参数；通常先用 `0`。旧配置的 `delay` 实际被播放器当成 easing 的回退值，**不是执行延迟**。延迟变化应使用 `beats[].at`。

以巧克力女仆模型为例：

| 变量 | 常见标注值 | 调整注意点 |
| --- | --- | --- |
| `head_LR`、`head_UD`、`head_slant` | 通常 -30..30，0 为正面。 | 小幅尝试；主时间轴、叠加动作和鼠标注视也可能控制这些变量。 |
| `body_LR`、`body_UD`、`body_slant` | 通常 -30..30。 | 大幅度变化可能改变姿态或位置。 |
| `move_LR`、`move_UD` | 通常 -30..30，0 为原位。 | 调整后应在恢复阶段归位。 |
| `face_eye_open` | -10 惊讶、0 正常、5 半闭、10 闭眼、16 半笑、20 笑眼。 | 30 以上还有特殊表情，不能当普通开合量使用。 |
| `face_eyebrow` | 0 正常、20 生气、30 难过、40 笑。 | 另有中间和特殊值。 |
| `face_mouth` | 0 正常、10 生气、20 难过、30 笑。 | 控制嘴形，**不是张嘴幅度**。 |
| `face_talk` | 0 闭嘴、5 张嘴。 | 有声音时由播放器口型模块驱动，通常不要手动保持张嘴。 |
| `arm_type` | 0～4 对应腕 A～E。 | 不同服装的具体姿态可能不同，数值不是手臂角度。 |
| `face_tears`、`face_cheek` | 离散表情状态。 | 不能假定 0 一律代表关闭，应看 JSON 标注。 |

这些数值只帮助理解示例，移植到其他模型时应重新核对。

主时间轴也会写入表情变量。若手动设置刚出现就消失，先检查是否被时间轴覆盖，而不是把数值继续调大。无声闭眼示例将主时间轴清空，正是为了避免这种冲突。

当前语音播放会将基础 `face_talk` 归零，再根据声音能量添加口型差分，并使用运行时变量上限。`face_mouth` 仍可以决定笑、怒等嘴形；不要用固定的 `face_talk: 10` 模拟整句说话。

恢复阶段既要清空临时 diff，也要还原自己改动的变量。`平常` 能重置模型的一批表情变量，但不应假定它重置所有自定义参数。更改服装显隐、离散姿态等参数前，也应检查恢复值是否适合该模型。

## 8. 怎样安排语音与动作时间

先记录语音的实际时长。已有结果可在 `voice-analysis.json` 中按 `path` 查找 `durationMs`；更换音频后应重新测量，例如：

```bash
ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 sounds/chocola/h06.wav
```

结果单位是秒，乘以 1000 后再填入配置。`h06` 的实测时长为 2391ms，当前变化点是 1554ms。这个变化点是配布选择，**不会由公共库自动分析或计算**。

短促的惊讶声通常只需要一个初始动作；长句或拉长音可在语气发生变化的位置安排 `beat`。不要为了让每条语音都有变化而随意增加动作；没有实际变化需要时，省略第七项或使用 `beats: []`。

外层 `duration` 小于音频时长不会把音频剪短；播放器仍等待音频结束。把它设得很长，会让角色在说完后继续保持反应，期间不能再次触发。静音时没有实际声音，仍按配置时长和主时间轴演出。

## 9. 保持角色个性的方法

先决定角色在这条语音里的态度，再选动作。例如巧克力的“明快回应”可以搭配明显的笑容和点头；“轻轻抱怨”则先摇头，再以疑问表情平复。不要因为角色开朗，就把所有抗议声音也配成持续微笑。

迁移到另一角色时，应分别考虑接受抚摸的方式、惊讶幅度、拒绝的直接程度和恢复表情。只替换 `sounds/` 路径，会保留同一套演出，不能产生角色个性。

六位主要角色的性格参考 [NEKOPARA 官方中文角色介绍](https://nekopara.com/cn/character/)，具体演出是本项目的设计选择。芙蕾兹、牛奶和幼年版本的一些配布细节仍是设计推定。

现有 `voice-analysis.json` 的机器转写对叫声、呼噜、拉长音尤其不可靠。音量和音高也不能单独证明高兴、生气或不适。调整情绪时以实际试听为准，并同步更新记录中的动作关联及可信度，不把机器猜测写成已核实台词。

## 10. 调整之后如何检查效果

打开壁纸的正常角色页面，例如本地的 [默认巧克力页面](http://127.8.8.8/show/)，用原有角色菜单切换服装，再进行实际触摸：

1. 先点击头部或脸部，确认初始表情与播放声音一致。随机池有多条声音时，需要等待上一次恢复，再重复点击检查其他条目。
2. 对有 `beats` 的声音，确认中途切换没有重播语音，也没有覆盖成矛盾情绪。
3. 等反应结束，确认嘴部闭合、临时动作清空、位移恢复，可以继续触发。
4. 检查实际命中范围，留意眼部、脸部和头部区域重叠造成的优先级差异。
5. 切换同角色其他服装，检查动作标签、变量、姿态和恢复动作仍适用。

先确定语气时，可以单独打开对应 WAV 文件试听。要确认实际触摸选中了哪条语音，可在浏览器开发者工具的 Network 面板查看 `sounds/` 请求。无需为此增加壁纸内的调试界面。

控制台中应检查音频请求是否成功、有无 JavaScript 或音频解码错误。出现 `NekoReactions is not defined` 或动作静默失效时，先检查脚本是否加载了正确版本、公共库是否先于角色配置加载，以及动作标签是否存在。

脚本 URL 使用文件修改时间更新缓存。修改语音、动作或配置覆盖范围后，也应同步维护相应分析记录；这些记录帮助核查配置，不能替代实际观察和试听。

## 11. 新旧版本兼容性

| 使用方式 | 能否使用当前配布 |
| --- | --- |
| 只把当前角色文件复制到原来的页面 | 简写依赖 `NekoReactions`，旧页面不加载公共库时会报错。 |
| 旧页面先加载 `reaction-library.js`，保留本项目修改前的 `main.js` | 支持初始反应、语音、diff 数组与恢复；忽略新增的 `beats`、`recoveryDuration`，口型仍采用旧行为。 |
| 使用完整对象写法，保留修改前的播放器 | 可避免 `create()` 的依赖，但同样没有新增的中途演出功能。更早版本还需核对其字段支持。 |
| 同步更新角色配置、公共库、`index.php` 和 `main.js` | 使用当前完整配布效果。 |

`index.php` 的配置外改动负责加载公共库和更新脚本缓存；`main.js` 的改动负责中途变化、恢复间隔、口型修正及异常清理。这些是动作配布的运行依赖。角色选择继续使用原来的页面路径与菜单。

如果只需要旧格式静态反应，可以手写完整对象并保留初始动作和恢复动作；配置本身不能让旧播放器自动获得分阶段播放能力。
